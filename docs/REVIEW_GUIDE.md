# Guide de revue

Une revue de code doit être précise, constructive et vérifiable.

## Points à examiner

- Le changement répond-il au problème annoncé ?
- Les tests reproduisent-ils le bug ou le comportement attendu ?
- Les limites sont-elles documentées ?
- Les données entrantes sont-elles validées ?
- Les chemins chauds évitent-ils les allocations inutiles ?
- Les erreurs importantes sont-elles visibles ?
- La documentation technique est-elle cohérente ?
- Les règles de sécurité et de licence sont-elles respectées ?

## Formulation des commentaires

Un commentaire de revue utile indique :

- le problème observé ;
- son impact ;
- le fichier ou le scénario concerné ;
- une correction ou un résultat attendu.

Évitez les commentaires vagues ou dirigés contre la personne.
