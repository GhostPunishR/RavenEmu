# Code de conduite de RavenEmu

## Notre engagement

RavenEmu souhaite offrir un espace de collaboration accueillant, respectueux et
sûr pour toutes les personnes qui participent au projet.

Ce code s'applique aux issues, pull requests, discussions, revues, espaces de
communication liés au projet et interactions publiques réalisées au nom de
RavenEmu.

## Comportements attendus

Les personnes participant au projet doivent :

- rester respectueuses, même en cas de désaccord ;
- critiquer le code ou une décision, pas la personne ;
- fournir des retours précis et constructifs ;
- accepter les corrections et reconnaître les erreurs ;
- respecter le temps des mainteneurs et des contributeurs ;
- protéger les données privées et les informations de sécurité ;
- citer les sources techniques utilisées ;
- respecter les licences et les droits d'auteur ;
- aider les nouveaux contributeurs à comprendre le projet.

## Comportements interdits

Ne sont pas acceptés :

- insultes, menaces ou attaques personnelles ;
- harcèlement public ou privé ;
- discrimination ;
- propos haineux ou sexualisés ;
- intimidation ;
- publication d'informations privées sans autorisation ;
- pression pour obtenir une réponse immédiate ;
- spam ou perturbation volontaire des échanges ;
- fausse attribution de travail ;
- ajout volontaire de code malveillant ;
- publication publique d'une vulnérabilité non corrigée avec des détails
  exploitables ;
- partage de ROM, BIOS, clés, sauvegardes ou autres données protégées.

## Désaccords techniques

Les désaccords doivent être résolus à partir de :

- la documentation matérielle ;
- les tests reproductibles ;
- les mesures ;
- les contraintes d'architecture ;
- l'impact sur les utilisateurs.

Une décision de mainteneur peut être contestée avec des arguments techniques,
mais elle doit être respectée tant qu'elle n'est pas remplacée.

## Signalement

Un comportement inapproprié peut être signalé au mainteneur `@GhostPunishR`.

Lorsque le signalement contient des informations sensibles, utilisez un canal
privé. Ne publiez pas de données personnelles dans une issue publique.

Un signalement utile indique :

- le lieu et la date de l'incident ;
- les personnes impliquées ;
- une description factuelle ;
- les liens ou captures nécessaires ;
- l'effet sur la participation au projet.

Les signalements seront examinés avec discrétion. L'identité de la personne qui
signale ne sera pas diffusée sans nécessité ou accord.

## Mesures possibles

Selon la gravité et la répétition, les mesures peuvent comprendre :

1. rappel privé des règles ;
2. avertissement formel ;
3. limitation temporaire de participation ;
4. suppression de commentaires ou de contenu ;
5. fermeture d'une discussion ;
6. refus d'une contribution ;
7. exclusion temporaire ou permanente des espaces du projet.

Les menaces crédibles, la publication de données privées, le harcèlement grave
ou l'ajout de code malveillant peuvent entraîner une exclusion immédiate.

## Responsabilité des mainteneurs

Les mainteneurs doivent :

- appliquer ces règles de manière cohérente ;
- éviter les conflits d'intérêts ;
- protéger les informations sensibles ;
- expliquer les décisions lorsque cela est raisonnable ;
- corriger ou retirer un contenu inapproprié ;
- traiter les contributeurs avec équité.

## Bonne foi

Une erreur de formulation isolée peut être corrigée par une discussion calme.
Ce code vise à protéger la collaboration, pas à sanctionner les désaccords
honnêtes.
