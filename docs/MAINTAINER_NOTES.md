# Notes de maintenance communautaire

Ce document aide à traiter les contributions de manière cohérente.

## Revue d'une pull request

Vérifier :

- la portée du changement ;
- l'originalité du code ;
- les licences ;
- les tests ;
- les limites connues ;
- les performances ;
- la sécurité ;
- la documentation.

## Fusion

Une pull request ne doit pas être fusionnée uniquement parce que la CI est
verte. La revue doit également vérifier le comportement fonctionnel et les
risques de régression.

Les remarques de priorité élevée doivent être corrigées ou explicitement
acceptées avant fusion.

## Vulnérabilités

Les rapports de sécurité restent privés jusqu'à la disponibilité d'un correctif
ou jusqu'à une décision de publication coordonnée.

## Modération

Appliquer le code de conduite de manière factuelle, proportionnée et cohérente.
Éviter de publier les détails privés d'un signalement.
